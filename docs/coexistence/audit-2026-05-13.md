# Coexistence audit — 2026-05-13

Whole-app re-audit driven by the 2026-05-12 post-mortem on the
`ht_checkins` single-room cardinality gap. Seven parallel tracks audited
schema, sync, reads, features, concurrency, identifiers, and operations.

**Source:** Seven `codebase-auditor` agents reading the relevant subset of
the codebase + `docs/legacy-app/` + `docs/legacy-spike/`. Read-only.

**Total findings:** 120 — 15 CRIT • 35 HIGH • 42 MED • 28 LOW.

The headline conclusion: **the app is NOT standalone-ready and has good
availability observability but almost no correctness observability**. The
multi-room cardinality bug discovered on 2026-05-12 is one instance of a
broader pattern: every layer was designed against intuition before the
legacy references existed, and the references' arrival never triggered a
re-audit. This audit closes that loop.

## Top-level cross-cutting themes

These are the patterns that recur across multiple tracks. Remediation
addresses themes, not individual findings.

### Theme 1 — Cardinality asymmetry (the source of the post-mortem)

**Findings:** T1 CRIT-1, T2 CRIT-1, T3 CRIT-2, T3 HIGH-1, T3 HIGH-3, T4 HIGH-1, T5 HIGH-1, T5 HIGH-2.

`ht_checkins` has one `cin_room_id NOT NULL`; legacy `HT_CheckIn_Ds` is
one row per room. Every layer inherits the single-room assumption:
the writeback recipe emits one Ds row; the sync mapper picks
`first_room_no`; the dashboard joins on `cin_room_id` so secondary
rooms are invisible; the calendar's `seenIds` dedup drops rooms 2..N
of multi-room bookings.

Same shape elsewhere:
- `ht_payments` collapses 6 legacy tables (`HT_CheckIn_Pay` + `HT_Receipt_H/Ds` + `HT_Invoice_H/Ds` + `HT_Bill_Debt_H/Ds`) into one row → split-tender lost, VAT invoices have no home, multi-line payments impossible. (T1 CRIT-2.)
- `HT_Room_Status` (the booking calendar's source) has no PG canonical at all. (T1 HIGH-4.)
- `HT_Round_Bill` (cashier shift gate) has no PG canonical → cash-drawer reconciliation impossible. (T1 HIGH-5.)
- `HT_Products` is mirror-only but `ht_inventory_items` exists with no link → stock invariant broken end-to-end. (T1 CRIT-3.)
- `ht_rates` has wrong axis (weekday/weekend) vs legacy `HT_Rooms_Price`'s `(Room_Type, Cust_Type)` matrix. (T1 CRIT-4.)

### Theme 2 — Reads from demoted legacy mirrors

**Findings:** T3 HIGH-4, T3 HIGH-5, T3 MED-3.

Phase 5.5 (2026-04-28) demoted `ht_*_legacy` mirrors to drift-detection
only. The dashboard migration (2026-05-11/12) updated `/api/stats`,
`/api/rooms`, calendar — but missed `/api/occupancy`, all of
`/api/customers/*`, and the calendar's `mode=New` branch which still
fetches BOTH mirror AND canonical (silent dedup-by-key risk).

Customer list, booking history per customer, "last visit", "total
stays" — all under-reported since 2026-04-28. The occupancy trends
chart is wholly broken for that window.

### Theme 3 — UTC vs Bangkok timezone in display

**Findings:** T3 MED-1, T3 MED-2, T6 HIGH-1.

`CURRENT_DATE` and `EXTRACT(HOUR FROM NOW())` are UTC. CLAUDE.md says
display layer treats times as Bangkok. Between 17:00 UTC and 00:00 UTC
(00:00–07:00 BKK), "today" check-out tile misses checkouts done in
early BKK morning. The 06:00 BKK morning-flip rule fires at 13:00 BKK
because `EXTRACT(HOUR FROM NOW()) >= 6` is computed in UTC.

Writeback recipes mostly fixed (Wave 1 + Wave 5b) but `booking_create`,
`payment`, `checkout`, `mark_clean` still recompute `Utc::now()`
multiple times within a single recipe → can straddle BKK midnight.

### Theme 4 — Reconcile is named but doesn't reconcile

**Findings:** T2 CRIT-3, T7 CRIT-1, T7 HIGH-1.

The scheduler/sync.rs reconcile job is `DiffOnly` by default. It only
writes to `ht_reconcile_log` — never repairs canonical state. The
alert threshold (50+ rows/hr) is calibrated for ledger drift; a
single multi-room folio drifts once per Cin_no and never trips the
threshold. `ack_*_mirror` writes the MSSQL hash into the mirror's
`sync_hash` column so subsequent ticks short-circuit even though the
canonical row is still wrong. There is no level-triggered alert on
`SELECT COUNT(*) FROM ht_reconcile_log WHERE resolved_at IS NULL`.

The system has good availability observability and almost no
correctness observability.

### Theme 5 — Payment concurrency under iHOTEL absolute-write

**Findings:** T5 CRIT-1, T5 HIGH-4.

The writeback payment recipe does additive UPDATE on `HT_CheckIn_H.Total_Price_Pay`. iHOTEL's save-payment uses absolute SET=. Spike §6
validated booking-edit race-safety, NOT payment. Interleaving:
writeback's additive commit happens, then iHOTEL's absolute write
overwrites with its pre-computed total → our payment is silently
dropped from the legacy view.

Same flavor on checkout: absolute write clobbers a payment that
committed between PG read and MSSQL write.

The TABLOCKX MAX+1 allocator remains race-safe. The Wave 4 H11
@@TRANCOUNT guard works. The bug is in column-level concurrency the
spike didn't enumerate.

### Theme 6 — Schema column drops

**Findings:** T1 HIGH-2, T1 HIGH-3, T2 HIGH-4, T2 MED-5.

The sync mappers drop columns silently because they project a subset
of the legacy schema. Customer mapper drops 9–20 columns including
`Cust_Sex`, full address tuple, `Cust_Price_Over` (running debt
balance — business-critical). Room mapper drops `Room_Use_Count`,
`Room_X/Y` (grid layout), `Room_Power_*`. Payment projection drops
`Cin_Pay_Free` (discount tender) and `Cin_Pay_web` (online tender).

Reconcile hash hides this because the hash is computed over the same
narrow projection on both sides.

### Theme 7 — Missing CT mappers / dangling subscriptions

**Findings:** T2 HIGH-3, T2 HIGH-5, T7 HIGH-3.

`HT_CheckIn_Other_People` has no CT enablement OR mapper, so
`ht_guest_registry` is silently stale — TM.30 immigration reporting
broken. `HT_Rooms_Cancel` is CT-enabled but has no mapper (dangling
subscription, CT retention runs forever without a consumer).
Fingerprint covers 15 writeback tables but misses 4 CT-watched mirror
tables (`HT_CheckIn_Product`, `HT_Deposit`, `HT_Bill_Debt_H/Ds`).

### Theme 8 — Features that force iHOTEL fallback

**Findings:** T4 CRIT-1 (refunds), T4 CRIT-2 (RR.4), plus 9 HIGHs.

The app is not standalone:
- **Refunds / negative payments** blocked at service layer (CRIT — daily blocker).
- **RR.4 Thai government registry** has no export (CRIT — legal requirement).
- Extend-stay service exists but no HTTP route or UI (HIGH — common operational request).
- Room-change mid-stay read-only (HIGH).
- Coupon issuing read-only (HIGH).
- POS / sales-to-room module missing (HIGH).
- Invoice has no VAT / tax_id / inv_no (HIGH — corporate guests).
- Round-bill / shift discipline missing (HIGH — cashier accountability).
- Permission model too coarse (HIGH — only Admin + Receptionist).

### Theme 9 — Operational observability gaps

**Findings:** T7 CRIT-2, T7 CRIT-3, T7 HIGH-2, T7 HIGH-4.

- `/api/new/sync/status` reads `sync_status` (4 entities) instead of `legacy_sync_status` (16). 12 CT-tracked entities have no health surface.
- No alert on CT watermark stall; the shadow-mode 2-day retention trap relies on already-being-too-late.
- Writeback queue depth has no proactive alert; only per-job exhaustion alerts.
- No coexistence smoke test in CI — the test-backend job runs against empty PG with no MSSQL service container.

### Theme 10 — Existing-matches idempotency too narrow

**Findings:** T2 HIGH-2, T5 HIGH-1, T2 LOW-3.

`existing_matches` for checkin/booking mappers compares status + totals
+ checkout_time only. Missing: `cin_room_id`, `cin_book_id`, `cin_checkin_time`,
`cin_expected_checkout`. A pure room-change in legacy (move guest
303→403) idempotency-skips on the watcher side; canonical stays
stale.

Compounded by `parent_loader::fetch_rows` having no `ORDER BY` →
`first_room_no` flips non-deterministically across ticks.

## Proposed remediation tracks

Eight remediation tracks. Each is an audit-style wave: scoped, severity-graded, deployable. Ordering is by **operational risk**, not by audit-track number. CI runs serial deploys so the tracks themselves serialize.

### Track A — Read-path triage (quick wins, biggest UX impact)
- T3 HIGH-4 — `/api/occupancy` → canonical
- T3 HIGH-5 — `/api/customers/*` → canonical (3 mirror reads)
- T3 MED-3 — Calendar new-mode drop legacy fetch
- T3 CRIT-1 — Inactive-room layout reconciliation (`58 = 23+34` mystery)
- T3 MED-1 + MED-2 — Bangkok timezone for `today`/`06:00` logic
- T6 HIGH-1 — `Utc::now()` once-per-recipe in remaining 4 recipes

Estimate: 1 wave, ~200 LOC, low risk. Fixes most user-visible read-side discrepancies.

### Track B — Multi-room canonical schema (the big one)
- T1 CRIT-1 — Add `ht_checkin_rooms` junction
- T1 CRIT-2 — Split `ht_payments` into payment + payment_lines + receipts
- T2 CRIT-1 — Rewrite checkin mapper to emit junction rows
- T2 HIGH-2 — Widen `existing_matches`
- T2 HIGH-1 — `ORDER BY` in `parent_loader::fetch_rows`
- T3 CRIT-2 — Calendar dedup key includes room
- T3 HIGH-1 + HIGH-3 — Today-checkins/outs aggregate by folio
- T4 HIGH-1 — Multi-room walk-in UX
- Backfill bin for existing folios

Estimate: 4–5 waves, ~1500 LOC, schema migrations. **Highest risk + highest reward.**

### Track C — Payment concurrency hardening
- T5 CRIT-1 — Payment recipe: re-aggregate `Total_Price_Pay` from `HT_CheckIn_Pay` rows under UPDLOCK+HOLDLOCK
- T5 HIGH-4 — Checkout: same pattern
- T5 HIGH-3 — `mark_clean` idempotency window for `HT_Housewife`
- T2 CRIT-2 — Project `Cin_Pay_Status` so cancelled payments are filtered

Estimate: 1 wave, ~150 LOC, requires a receptionist-driven coexistence test.

### Track D — Operational observability
- T7 CRIT-1 — Cardinality-aware reconcile (row-count comparison before ack)
- T7 CRIT-2 — `/api/new/sync/status` reads `legacy_sync_status`

- T7 HIGH-2 — Writeback queue depth alert

### Track E — Sync gaps + column expansion

## What goes wrong if we do nothing

For each high-stakes risk, the operational consequence today:

| Risk | Today's blast radius |
|---|---|
| Multi-room check-in invisible | Receptionist sees 1 room occupied when 3 are — overbooks the visible-vacant rooms |
| `/api/customers` reads demoted mirror | Customer "total stays" undercounts since 2026-04-28; VIP loyalty broken |
| `today_check_outs` UTC bug | Morning-shift dashboard misses checkouts done 00:00–07:00 BKK |
| Refunds blocked | Any guest complaint = iHOTEL fallback; PG diverges |
| RR.4 missing | Standalone operation is illegal (Thai immigration requirement) |
| Payment concurrent additive UPDATE | Concurrent iHOTEL save-payment silently drops our payment from legacy view |
| Reconcile never repairs | Multi-room divergence accumulates forever; no alert fires |
| Watermark stall not alerted | Shadow-mode 2-day CT retention cliff hits before operator notices |
| Round-bill missing | Cash variance reports impossible; cashier accountability gone |
| `HT_CheckIn_Other_People` no sync | TM.30 immigration reports under-count foreign guests |
